# benchmarks

The harness behind readb's efficiency research: does an agent answer questions about an OKF
bundle faster and cheaper with readb than without?

- **v1** — [`docs/dev/research/agent-efficiency.md`](../docs/dev/research/agent-efficiency.md)
- **v2** — [`docs/dev/research/agent-efficiency-v2.md`](../docs/dev/research/agent-efficiency-v2.md),
  pre-registered in
  [`agent-efficiency-v2-preregistration.md`](../docs/dev/research/agent-efficiency-v2-preregistration.md)

Development material — excluded from the sdist, not part of the readb package.

## Layout

| File | What it is |
| --- | --- |
| `generate_corpus.py` | The platform bundle (services, runbooks, incidents, decisions) plus its ground truth, computed in plain Python and written **outside** the bundle. `--tidy` renders one uniform style; the default varies the styling without changing the meaning. |
| `generate_backlog_corpus.py` | The task-tracker bundle — an invented product's engineering backlog, whose concepts point at each other and whose bodies carry the tokens the body questions extract. |
| `battery.py` | The 26 pre-registered questions, their strata, their answer protocol, and the scorer. |
| `run_benchmark.py` | Runs the matrix of arm × question × model × repeat and appends one JSON line per run. |
| `analyze.py` | Aggregates a results file into the published tables, and runs the pre-registered endpoint tests. |
| `test_harness.py` | Tests for the scorer, the cost model, the integrity checks, the exclusion rule, the statistics, and the corpus invariants. |
| `results/` | A `manifest-<batch>.json` per batch and the generated analyses. Raw per-run records (`*.jsonl`) and transcripts are gitignored — they are regenerated by a run, and megabytes of a third party's runtime internals do not belong in a public repository. |

Run the harness suite by name — it is outside the package's `testpaths`:

```sh
uv run pytest benchmarks
```

## The five arms

| Arm | Prompt | Environment |
| --- | --- | --- |
| `baseline` | Orientation only | readb kept off `PATH` |
| `shell-coached` | Orientation plus a worked recipe, one per corpus family | readb kept off `PATH` |
| `readb-bare` | Orientation plus `readb query` / `readb schema` syntax | readb on `PATH` |
| `readb-nudged` | `readb-bare` plus one frozen routing sentence | readb on `PATH` |
| `readb-skill` | Identical to `baseline` | readb and `uv` on `PATH`, the repository's plugin loaded so the shipped skill is discoverable |

`shell-coached` exists because readb's honest competitor is a shell pipeline, not an uncoached
agent. Its recipe is **data, not prose**, so the exact commands an arm is shown are executed
against the real corpus before any measured run — and, where the answer is known, checked against
ground truth. A recipe that runs and under-counts is worse than one that fails: it makes the
competitor a straw man, which is worth more to readb's published ratio than any real effect.

`readb-nudged` carries routing guidance as an **arm rather than an edit**. Folding it into
`readb-bare` would silently redefine what v1 measured, and adjusting prompt text until an agent
picks the tool the experimenter prefers is tuning the benchmark until it flatters the tool. The
sentence is frozen in `run_benchmark.py`; changing it after a measured run retracts that arm.

`uv` is on the skill arm's `PATH` alone. It was once a requirement — the shipped skill's leading
example was `uvx readb`, and an arm without `uv` measured that failure instead of the skill, which
is exactly what happened to the first `readb-skill` batch (retracted; see the v1 concept's
finding 6). The skill now leads with the bare binary, so `uv` is kept only as insurance against an
arm failing on something other than what is being measured.

Every arm runs with `--setting-sources ""`, so no personal configuration, skill, hook or MCP
server reaches any of them; arm C differs from arm A by exactly one loaded skill. `--safe-mode`
is deliberately *not* used — it suppresses `--plugin-dir`, which would collapse arm C onto arm A
without any visible sign.

## Reproducing v2

Four corpora, then four blocks. `$C` below stands for the four `--corpus` flags, which every
block passes identically.

```sh
python benchmarks/generate_corpus.py --out /tmp/ops \
    --truth /tmp/truth_ops.json --concepts 600 --seed 24
python benchmarks/generate_corpus.py --out /tmp/ops-malformed \
    --truth /tmp/truth_mal.json --concepts 600 --seed 24 --malformed 12
python benchmarks/generate_corpus.py --out /tmp/ops-tidy \
    --truth /tmp/truth_tidy.json --concepts 600 --seed 24 --tidy
python benchmarks/generate_backlog_corpus.py --out /tmp/backlog \
    --truth /tmp/truth_backlog.json --tasks 170 --sprints 22 --seed 24

uv venv /tmp/benchvenv
VIRTUAL_ENV=/tmp/benchvenv uv pip install "readb==0.2.0"

C="--corpus ops=/tmp/ops,/tmp/truth_ops.json \
   --corpus ops-malformed=/tmp/ops-malformed,/tmp/truth_mal.json \
   --corpus ops-tidy=/tmp/ops-tidy,/tmp/truth_tidy.json \
   --corpus backlog=/tmp/backlog,/tmp/truth_backlog.json \
   --readb-bin /tmp/benchvenv/bin/readb"

# 1. Sonnet — five arms, 26 questions, three repeats (390 runs)
python benchmarks/run_benchmark.py $C --results benchmarks/results/v2-sonnet.jsonl \
    --models claude-sonnet-5 --repeats 3

# 2. Haiku — four arms, no skill arm (312 runs)
python benchmarks/run_benchmark.py $C --results benchmarks/results/v2-haiku.jsonl \
    --models claude-haiku-4-5 --repeats 3 \
    --arms baseline,shell-coached,readb-bare,readb-nudged

# 3. Floors — the fixed harness overhead, per arm and model (27 runs)
python benchmarks/run_benchmark.py $C --results benchmarks/results/v2-floor.jsonl \
    --models claude-sonnet-5 --repeats 3 --questions q1 --floor
python benchmarks/run_benchmark.py $C --results benchmarks/results/v2-floor.jsonl \
    --models claude-haiku-4-5 --repeats 3 --questions q1 --floor \
    --arms baseline,shell-coached,readb-bare,readb-nudged

# 4. Messy against tidy — the same questions, both renderings (54 runs), one file:
#    resume keys on the corpus, so the second half is not mistaken for the first
python benchmarks/run_benchmark.py $C --results benchmarks/results/v2-sweep.jsonl \
    --models claude-sonnet-5 --repeats 3 --questions q2,q3,q15 \
    --arms baseline,shell-coached,readb-bare
python benchmarks/run_benchmark.py $C --results benchmarks/results/v2-sweep.jsonl \
    --models claude-sonnet-5 --repeats 3 --questions q2,q3,q15 \
    --arms baseline,shell-coached,readb-bare --corpus-map ops=ops-tidy
```

The working root must not sit under a path containing `readb`: the agent's cwd reaches its system
prompt, so the path alone would prime every readb-free arm. The harness refuses to start otherwise.

A preflight runs first and refuses to start unless each arm loaded the skills it should have, can
execute the binaries it needs on its own `PATH`, and every coached command runs against the real
corpus and finds what the ground truth says is there.

Analysis. The pre-registered endpoints print first; everything after them is descriptive.

```sh
cat benchmarks/results/v2-sonnet.jsonl benchmarks/results/v2-haiku.jsonl \
    > benchmarks/results/v2-all.jsonl
python benchmarks/analyze.py --results benchmarks/results/v2-all.jsonl \
    --floor benchmarks/results/v2-floor.jsonl
python benchmarks/analyze.py --results benchmarks/results/v2-all.jsonl \
    --baseline-arm shell-coached
python benchmarks/analyze.py --results benchmarks/results/v2-sweep.jsonl --skip-endpoints
```

The sweep is analysed on its own: its three questions also appear in the main matrix, and folding
them together would weight those three twice.

A batch that is not the main matrix — a sweep, a re-measurement — passes `--skip-endpoints`, since
the endpoints are defined over the main matrix and would otherwise print a test of a subset. A
batch that re-measures a single arm has no baseline of its own to pair against; give it one with
`--baseline-from`.

## Costs and caution

v1's full 3-repeat matrix was **144 headless agent invocations** and its batches came to about $25
in total. v2's is **783** across four blocks and two models, and takes a few hours serially — which
it is deliberately, so no arm inherits a busier machine than another. `run_benchmark.py` is resumable — a cell already present in
the results file is skipped — and `--budget` / `--total-budget` are runaway guards, not live
constraints.

Two rules learned the hard way, both now enforced in code:

- **Give every batch its own `--results` stem.** Transcripts and manifests are named after it. A
  shared name means a later batch overwrites an earlier batch's evidence — which is how 68
  transcripts behind published runs were lost before the harness learned to refuse.
- **Never hand-compute a figure the analyzer could emit.** Four wrong cells reached a published
  table that way.

And one learned from v1's design review, enforced by a test:

- **A tool-choice measurement is a result, never a reason to edit a prompt.** The moment prompt
  text is adjusted because an agent picked the "wrong" tool, the benchmark measures the adjusting.
